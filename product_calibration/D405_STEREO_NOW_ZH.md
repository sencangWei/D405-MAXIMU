# D405 自由拟合诊断入口（非客户正式流程）

当 D405 已固定、产品身份已建立，但正式产品流程尚未完成时，使用独立候选命令：

```bash
cd /home/robot/ego_vio_calib_kit
./camera_bench_04_d405_stereo.sh D405_260322273737
```

该命令是研发/售后诊断入口，不会替换客户正式流程使用的 Intel 出厂参数。它会校验
产品档案中的 D405 序列号和固件，读取当前双 IR `1280×720@30 Y8` 工厂基线，随后
分别采集：

1. 求解集：整机固定，只移动 AprilGrid，覆盖近、中、远、画面四角和多个倾角。
2. 独立留出集：重新移动 AprilGrid 覆盖九宫格；这批图不进入 Kalibr 求解。

留出集窗口会显示 3×3 网格：黄色框是当前必须完成的格，圆点是程序根据 tag ID
计算出的整张板中心；绿点表示位置合格，红点表示太靠近格线。顶部同时显示
`板中心当前位置`和`尚缺`列表。程序从左上到右下逐格推进，每格至少15个稳定检测帧，
未完成当前格不会进入下一格。

每组在终端按回车后才启动相机，约 3 秒后会弹出名为
`ego_vio calibration camera` 的实时窗口。窗口显示绿色 tag 边框、识别数量、当前动作和
未达标原因；按回车前没有画面属于正常时序，不是相机故障。

相机打开后会先隔离至少 60 组连续配对双 IR 帧（约 2 秒）。预热期间若设备帧号
跳变，会保存预热丢帧证据并从头累计连续帧；预热完成后的下一帧才进入正式窗口。
诊断求解集和留出集都必须零丢帧，健康证据保存在各录制目录的
`camera_capture_health.yaml`。

命令自动运行双目 Kalibr，检查左右重投影、基线偏差以及独立留出集纵向极线误差
P95。所有原始图、bag、求解文件、日志、SHA-256 和报告保存在：

```text
camera_bench_results/时间戳_d405_stereo_candidate/
```

候选报告固定为 `release_eligible: false`，不会绕过正式五个必需阶段，也不得将自由拟合
`camchain` 导入客户产品。正式第4步请运行：

```bash
./calibrate_04_d405_factory.sh 产品编号
```

只有售后分析 factory 极线验收失败原因时，才使用本文件的自由拟合结果作对照。

当前采集链的转换器仍要求绑定的 IMU 串口可读写，虽然 IMU 数据不参与双目内外参求解。
