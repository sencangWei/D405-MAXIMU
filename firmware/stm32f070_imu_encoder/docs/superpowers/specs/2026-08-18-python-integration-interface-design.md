# STM32 IMU + AS5047P Python 对接接口设计

## 目标

交付一个不依赖任何具体 APP 或 GUI 框架的 Python 接口包。调用方只需指定
CP2102N 的串口名，即可持续获得由 STM32 已经完成硬件侧配对的 KT-EX9 IMU
数据和 AS5047P 角度数据。

本次不修改第三方 APP，不设计 UI，也不在 PC 端重新按串口到达时间匹配 IMU
与编码器。

## 交付结构

- `tools/imu_encoder_protocol.py`
  - 定义 63 字节联合帧、状态位和结构化数据类型。
  - 负责 CRC-16/CCITT-FALSE、断包、粘包、噪声重同步和 32 位计时器回绕。
  - 不导入 `pyserial`，可使用模拟数据独立测试。
- `tools/imu_encoder_client.py`
  - 负责 CP2102N 串口生命周期和后台接收线程。
  - 使用有界队列向调用方提供 `read(timeout)`，避免慢速 APP 阻塞串口接收。
  - 暴露最近样本和接收统计；关闭操作可重复调用且不会遗留线程。
- `tools/example_imu_encoder.py`
  - 展示连接、读取、状态判断和正常关闭的最小用法。
- `docs/IMU_ENCODER_PYTHON_INTERFACE.md`
  - 面向 APP 开发者的协议、API、错误处理、保存字段和验收说明。

现有 `tools/combined_capture.py` 保留为命令行采集工具，并改为复用协议模块，避免
形成两份协议实现。

## 公共数据模型

`CombinedSample` 至少提供以下稳定字段：

- PC 收到并完成解析时的 `pc_unix_ns`。
- STM32 输出序号、IMU 内部计数器和完整状态位。
- IMU 首字节 UART 接收时间、编码器 SPI 读取时间及二者差值，单位均为微秒。
- `gx/gy/gz`、`ax/ay/az`、温度。
- AS5047P 完整 16 位响应、14 位原始角度和角度值（度）。
- 原始 37 字节 IMU 帧和原始 63 字节联合帧，便于追溯。

状态位不被隐藏。即使编码器无效，仍返回 IMU 样本，由调用方根据
`encoder_valid` 决定是否显示角度。

## 客户端行为

默认通信参数为 921600 baud、8N1、无流控。`start()` 创建一个后台线程持续读取
串口；`read(timeout)` 从有界队列获取下一帧。队列满时丢弃最旧的、尚未被 APP
消费的样本，同时增加本地溢出计数，保证串口接收线程不因 GUI 或业务处理变慢而
阻塞。

客户端不替 APP 保存文件、不创建窗口、不解释业务动作。调用方可以在自己的线程
中阻塞读取，或定时轮询 `read(timeout=0)`。一个采集板对应一个客户端实例。

## 错误与恢复

- 帧头前的噪声会被丢弃并计数。
- CRC 错误帧不会返回给调用方，解析器继续寻找下一帧头。
- 版本或长度不支持时跳过候选帧并重新同步。
- 串口读取异常记录到客户端状态，并使后续 `read()` 明确报告接收线程错误。
- 用户主动 `close()` 后，阻塞读取应在有限时间内结束。
- STM32 flags 中的编码器错误、奇偶校验错误、IMU 计数缺口和队列溢出均原样暴露。

## 验证标准

自动化测试必须覆盖：

1. 单帧字段、IMU 浮点数、角度和 CRC 正确解析。
2. 任意分段输入和多帧粘连输入。
3. 噪声、错误 CRC、错误版本后的自动重同步。
4. 32 位微秒计时器回绕。
5. 后台客户端正常读取、超时、队列满丢最旧样本和安全关闭。
6. 现有命令行采集器继续通过原有测试。

由于当前没有接入实物板，自动化测试只证明软件接口行为；最终验收还需用真实
CP2102N 串口连续采集，并核对约 400 Hz 帧率、错误统计和角度变化。
