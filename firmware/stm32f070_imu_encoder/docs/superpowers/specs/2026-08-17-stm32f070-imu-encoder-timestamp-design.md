# STM32F070 IMU + AS5047P 联合采集设计

日期：2026-08-17

## 1. 目标与边界

在现有 IMU 转接板上使用 STM32F070F6P6 同时采集：

- KT-EX9-2J-2-F1 的 400 Hz UART 数据；
- AS5047P 的 14 位 SPI 角度；
- 同一 STM32 硬件定时器下的两个采集时间戳。

STM32 将二者封装为单一二进制帧，经 CP2102N 发送给 PC。编码器未连接或读取失败时，IMU 必须继续运行。

本版本不修改原理图或 PCB，不依赖 IMU DIO，不实现两个传感器由同一电气脉冲触发的严格同时采样，也不实现 USB 串口升级固件。首次烧录和救砖使用板上的 SWD 接口与 ST-Link。

## 2. 已确认硬件映射

| 功能 | STM32F070F6P6 引脚 | 外设 |
|---|---:|---|
| IMU_TX -> MCU_RX | PA3 / pin 9 | USART2_RX |
| MCU_TX -> IMU_RX | PA2 / pin 8 | USART2_TX |
| 编码器 CS | PA4 / pin 10 | GPIO |
| 编码器 SCK | PA5 / pin 11 | SPI1_SCK |
| 编码器 MISO | PA6 / pin 12 | SPI1_MISO |
| 编码器 MOSI | PA7 / pin 13 | SPI1_MOSI |
| MCU_TX -> CP2102N_RX | PA9 / pin 17 | USART1_TX |
| CP2102N_TX -> MCU_RX | PA10 / pin 18 | USART1_RX |
| SWDIO | PA13 / pin 19 | SWD |
| SWCLK | PA14 / pin 20 | SWD |

系统使用内部 8 MHz HSI 经 PLL ×12 得到 48 MHz，不要求外部晶振。STM32F070F6 没有 TIM2，因此使用 16 位 TIM3 以 1 MHz 运行，并在每次溢出中断中扩展高 16 位，形成 32 位微秒计数器。扩展计数约 71.6 分钟回卷一次；PC 端负责无歧义展开回卷。

## 3. IMU 接收与时间戳

KT-EX9 使用 USART2，921600 baud、8N1。有效帧固定为 37 字节：

- 帧头：`EB 90 22`；
- 字节 4..31：7 个小端 float；
- 字节 32..35：小端 `uint32` 计数器；
- 字节 36：字节 0..35 求和的低 8 位。

USART2 使用精简的 RXNE 接收中断。状态机在等待帧头时收到候选首字节 `0xEB`，立刻读取扩展后的 TIM3 微秒计数，并把该值附着到候选帧。只有后续帧头、长度和校验全部正确时，该时间戳才会输出。

该时间戳准确含义是“STM32 收到首字节并置位 RXNE 时的硬件计时器值”，不是 IMU 内部采样时刻，也不是 UART 起始位的定时器输入捕获。相对实际起始位存在约一个字节传输时间的固定偏移，另有少量中断响应抖动。

中断中只完成读寄存器、状态机推进、校验累加和入队，不进行浮点解析、SPI 等待或串口发送。有效 IMU 帧进入小型固定长度队列，由主循环处理；队列溢出会计数并置位状态标志。

## 4. 编码器读取

AS5047P 使用 SPI1，Mode 1、MSB first、750 kHz、16 位传输。48 MHz 外设时钟无法通过 SPI 的二次幂预分频精确得到 1 MHz，因此选择 48 MHz / 64 = 750 kHz，保持不高于已经验证过的 1 MHz。每个有效 IMU 帧触发一次角度读取：

1. 在第一次 CS 拉低前读取扩展后的 TIM3 微秒计数，记录 `encoder_read_us`；
2. 发送带偶校验的 `ANGLEUNC(0x3FFE)` 读命令；
3. CS 拉高并满足最小间隔；
4. 发送 NOP，取回上一个读命令的响应；
5. 检查响应偶校验和错误位，保留完整 16 位响应；角度为低 14 位。

PA6/MISO 启用弱上拉，使接口未连接时倾向读成 `0xFFFF` 并被错误位判无效。固件不因编码器错误停止 IMU 输出。

`encoder_read_us` 是 SPI 读取开始时刻，不代表 AS5047P 内部磁场采样的精确时刻。

## 5. PC 联合二进制帧

USART1 经 CP2102N 输出，921600 baud、8N1，使用非阻塞发送。每个有效 IMU 帧产生一个固定 63 字节联合帧，所有多字节整数均为小端：

| 偏移 | 长度 | 字段 |
|---:|---:|---|
| 0 | 2 | 同步头 `A5 5A` |
| 2 | 1 | 协议版本，初版为 `1` |
| 3 | 1 | 总帧长度，固定为 `63` |
| 4 | 2 | 状态标志 |
| 6 | 4 | STM32 输出序号 |
| 10 | 4 | `imu_first_byte_rx_us` |
| 14 | 4 | `encoder_read_us` |
| 18 | 4 | IMU 内部计数器 |
| 22 | 2 | AS5047P 完整 16 位响应 |
| 24 | 37 | 原始 KT-EX9 帧 |
| 61 | 2 | 字节 0..60 的 CRC-16/CCITT-FALSE |

状态标志初版定义：

- bit 0：IMU 帧校验通过；
- bit 1：编码器响应有效；
- bit 2：编码器错误位被置位；
- bit 3：编码器偶校验失败；
- bit 4：IMU 计数器不连续；
- bit 5：IMU 接收队列曾溢出；
- bit 6：PC 发送队列曾溢出；
- bit 7..15：保留为 0。

63 字节 × 400 Hz = 25.2 kB/s，包含 UART 起止位后约 252 kbit/s，低于 921600 baud。输出使用固定缓冲区，不使用动态内存、JSON 或运行时字符串格式化。

## 6. PC 工具

PC 工具负责：

- 从任意字节位置搜索 `A5 5A`，按长度和 CRC 重新同步；
- 解析原始 IMU 数据、计数器、编码器角度和状态；
- 展开 32 位 STM32 计时器回卷；
- 在收到联合帧时另记 PC UNIX 时间；
- 保存原始联合帧和可分析的 CSV；
- 统计帧率、IMU 计数器缺口、CRC 错误、编码器错误、队列溢出，以及 `encoder_read_us - imu_first_byte_rx_us` 的分布。

PC UNIX 接收时间只用于与相机或系统时间做后续对齐，不能替代 STM32 内部时间戳。真实端到端延迟和抖动测试需要连接实物；若要校准物理 UART 边沿到固件时间戳的误差，需增加逻辑分析仪或示波器。

## 7. 软件结构与验证

工程独立放在 `firmware/stm32f070_imu_encoder/`，不修改现有 VIO 主程序或 ESP32 临时测试固件。建议结构：

```text
firmware/stm32f070_imu_encoder/
  include/                 纯协议头文件
  src/                     STM32 初始化、ISR、采集与封包
  test/                    主机端协议单元测试
  tools/                   PC 串口接收与记录脚本
  docs/superpowers/        设计与实施计划
```

使用 STM32CubeF0 提供的 CMSIS 器件头文件和启动文件，时钟、GPIO、USART、SPI、TIM3 以及时间敏感的 USART2 RXNE ISR 均采用直接寄存器实现，避免未使用 HAL 模块和逐字节回调开销。主循环只在关中断复查确认无待处理工作后进入 WFI，避免“帧刚入队就睡眠”的竞争窗口。工程通过可复现的命令行构建，并生成可由 ST-Link 烧录的 ELF/BIN 文件。

无硬件阶段必须验证：

- KT-EX9 正常帧、坏校验、噪声与重新同步；
- AS5047P 命令偶校验和响应判定；
- 联合帧精确布局、大小端和 CRC；
- PC 解析器乱流重同步、分包、粘包和 32 位 MCU 计时回卷；
- 固件目标能完整编译并满足 STM32F070F6 的 32 KB Flash / 6 KB SRAM 限制。

上板阶段再验证实际 400 Hz、计数器连续性、角度有效性、长时间队列零溢出，以及延迟和抖动统计。
