## 起因

[[point-inspection-and-stitch-20260919]] ③ 留下的唯一线索：`batch5/g3` 第一个运动关键帧在
**帧 226（t=7.53s）**，比真值运动起手（t≈4.8s）晚 2.7s。本轮去试"把它提前，15mm 会不会消掉"。

## ① 收紧 `motion_keyframe_translation` 是【空转】

原提的 A/B（`0.15`→`0.03`）动不了任何东西：帧 226 触发时 `translation=0.0245, rotation=5.753deg`
⇒ **rotation 触发**，且 0.0245 本来就 < 0.03。151 次触发里 **101 次 rotation 单独触发 / 42 次 translation 单独**。

## ② 收紧 `motion_keyframe_rotation_deg` 5.0→1.0：只挪 4 帧

| | 第一个关键帧 | 触发值 | 帧≤226 的关键帧 |
|---|---|---|---|
| 基线 `5.0°` | 帧 **226** | 5.753° / 0.0245 | 1 |
| 变体 `1.0°` | 帧 **222** | 1.013° / 0.0075 | 4 |

**原因**：前 7.37s 的「视觉 vs IMU 先验旋转分歧」**一直 <1°**（帧 222 才 1.013°、帧 224 才 2.073°）。
⇒ **这个信号在静止段是平的，阈值够不到空洞**；任何低于 5.0 的阈值都只能把首帧放在 **222–226**。

## ③ 这个旋钮是【全局】的 ⇒ 做不出干净对照，而且撑爆工具链

收到 1.0° 让关键帧数涨 **3.4x**（前 459 帧 133 个 vs 基线全程 151 个）。
跑到**帧 1294/1799、512 个关键帧**时崩，**零产出**：

```
multiprocessing.managers.RemoteError: KeyError: '7c8e0fc1cc80'
  ← frame.py:220 get_mode() 走 mp.Manager() 的代理
```

**不是 OOM**（dmesg 无记录，内存 7G/62G）；**不是超时**（10:34 时进程仍活，12:20 自己崩）。
全仓历史：**跑完的最高 232 个关键帧**；`dense_motion_kf_v1` **250 且 `done=1`**。512 是从未 exercise 过的量级。

## ④ 两个必须立住的对照（否则上面不成立）

- **前端确定性 + scratch 调用等价**：同一命令行换回 `5.0°` 重跑 ⇒ 关键帧帧号序列 **151/151 逐位相同**，
  `trajectory_frames.csv` **逐位相同（最大逐元素差 0.000e+00）**。⇒ 差异可干净归给配置。
- **`aged_translation` 的量级是实测的**：触发器比的是"当前帧相对上个关键帧的平移"，
  在 `trajectory_frames.csv` 里实测：开头 6s 只有 **2e-5**（≈0.009mm），逐帧抖动 ~1e-5，帧 226 才跳到 0.0254。
  ⇒ **既有配置的 `aged_translation: 0.01 / 0.08` 在这个 take 上永远够不着**。
  旁证：`dense_motion_kf_v1`（`rot 2.0`+`max_gap 30`+`aged 0.01`）第一个关键帧**迟至帧 771**。

## ⑤ 对的那个杠杆：`aged_motion`（只补空洞，不改阈值）

`motion_keyframe_trigger()` 里 `aged_motion` 要求 `frame_gap >= maximum_frame_gap`
⇒ **只在"距上个关键帧很久"时才可能触发，恰好只补空洞**。
配置 `config/mast3r_slam_d405_offline_motion_kf_agedfill.yaml`（`max_gap_frames: 15` + `aged_translation: 1e-6`）。

**杠杆极干净**：帧 ≤411 时 51 个关键帧 vs 基线 37，**多出的正好 14**；开头（帧 ≤226）补了 **15** 个、基线 **1** 个
⇒ **轨迹其余部分的关键帧一个没动**。总 204 个，跑通。

## ⑥ ★ 结果：机理证实，但不是修法（两件事必须一起读）

```
运行          切点s  头残差  尾残差  段间互差  夹角   rmse①  p95①  max①  w10①
基线 5.0       7.53   3.75   12.34   17.68   8.71   20.62  36.50  52.51  16.6
对照 5.0 重跑   7.53   3.75   12.34   17.68   8.71   20.62  36.50  52.51  16.6  ← 逐位同基线
agedfill      7.53   2.63   14.61    8.88   6.73   23.85  44.31  61.13  19.9
```

1. **✅ 空洞【确实】是那 15mm 的贡献者**：段间互差 **17.68 → 8.88mm（减半）**、夹角 **8.71 → 6.73°**、头残差 3.75→2.63。
2. **❌ 但不是修法**：整体指标**全部变差**（`max①` 52.5→61.1、`p95①` 36.5→44.3），尾段对真值残差 **12.34 → 14.61**。
   ⇒ 解更"自洽"了，但更不准。
3. **⚠ 两种解释分不开**：变差既可能"零基线关键帧本身有害"，也可能"这组补法不好"。**没做更松的补法（如 max_gap 30）**。

⇒ **净结论：空洞是真的、确实在造这 15mm 的一部分；但用配置补它换来整体误差上升，不是能走通的修法。**
结合 ④（段间位移**不是**门判别量，PASS 那条正好在中位）⇒ **不要再沿"补开头关键帧"投入。**

> ⚠ **口径坑**：`stitch_ab.py` 印的 `rmse①/p95①/max①/w10①` 是 **① 前端原始轨迹 ×scale**，
> **不是产品链的，不可对门限读**（产品链参考 [[mast3r-chain-topology]]：① 3.75/12.34 → ④ 0.82/4.70）。
> ⚠ **脚本标签坑**：取键必须用路径末**两**段，只取 `parent.name` 会在 `.../kfab/` 下**同名静默覆盖**（本轮踩过）。

## ⑦ ★★ 后续结案：**「只在快段加密」这条靶向前提也被否掉了**（2026-09-20，§12）

本页的失败是个**全局**旋钮（`agedfill` 补全轨迹的关键帧、`rot 1.0` 全局加密 3.4×）。
因此当时留下一条**未被否证**的路线：**只在快速段加密关键帧**（靶向）。它成立的前提是
「峰**系统性地**落在长关键帧间隙里」—— 该前提已于同日实测**不成立**：

* **天然对照**（`tight` vs `sparse` 是**同一批 session 的真前端两跑**，关键帧密度差 **5×**：
  中位间隙 0.19s vs 0.93s）⇒ **MAX 中位 15.9 vs 14.3（sparse 略好）**，
  逐 session tight 胜 3 / sparse 胜 5，`corr(中位间隙, MAX)` = **−0.254（负）**。
* **n=1523 个间隙 + 速度三分层**：间隙长度 vs 误差 r=+0.096；扣掉速度后 +0.185（r²≈3%）；
  到最近关键帧距离 vs 误差 r=**−0.318（仅 3/18 为正，方向与「覆盖不足」相反）**；
  **高速半里塌成 −0.031** ⇒ 无独立解释力。
* 单看峰那个 1.68× 是**速度混淆**（关键帧**按运动量**放置 ⇒ 间隙长 ⟺ 跑得快，
  而峰本来就在快段，见 [[spike-attribution-20260919]]）。

⇒ **「关键帧密度」整族旋钮（全局 + 靶向）划掉**，与 ⑥ 的结论合流。
详见 [[mast3r-rerun-tail-v2-20260920]] §12（`peak_keyframe_context.py` /
`gap_error_profile.py` / `density_natural_experiment.py`）。
