## ★★ 09-20 证伪检验：这道 rot 门在很大程度上是**伪装成旋转的位置门**

证据目录 `reports/mast3r_g2_validation_20260919/rotation_gate_20260920/`（README 三稿）。
上面「分辨带 ≈1.75°」是**一阶启发式**；下面是**直接测量**，两者量级吻合。

**证伪设计**：若「门 = 真姿态误差 ⊕ 位置污染」成立 ⇒ 门应随 ATE 上升、姿态口径**不随**。
拿两条链（`fused` + `vins_raw`）共 **n=16** 试（`contamination_falsification.py`）：

| 量 | corr(ATE) | |
|---|---|---|
| 门（位置口径 `rigid_align`） | **r=+0.894, p<1e-4** | 强显著 |
| 姿态口径 `orientation_align` | r=+0.373, **p=0.155** | **不显著** |

逐 cell：**ATE 变化 45 倍（2.8→127.5mm），姿态误差恒 1.04–1.42°（极差 0.38°）**，
同一批 cell 的门从 1.87° 涨到 13.09°。**ATE≥10mm 的 8 个 cell 门 0/8 过；<5mm 的 3/4 过。**
三条回归外推「门=2.0° ⟺ ATE」= **3.9 / 4.1 / 2.5mm**，彼此自洽。

⇒ **可执行目标：把 fused 的 ATE 中位从 ~6mm 压到 ≲4mm 就能过 rot 门。**
⇒ 也修正了本条目的措辞：不是「门在地板下面没法弄」，而是**门实际在量位置**。

**门的构成**（`rotation_error_decomposition.py`，8 cell 中位）：
`2.38° = √(真姿态 1.20² + 位置污染 1.18²)`；纯姿态口径 **8/8 全过 2.0°**。
真姿态误差 1.20° 与 OpenVINS 文献静态初始化 **1.15°(1σ)** 同量级 ⇒ 姿态侧无空间。

**⚠ 但「全是不可观测 yaw」不成立**：按 GT 世界系重力轴拆，
门口径 yaw 1.50° / tilt 1.70°（yaw>tilt 只 3/8），姿态口径 yaw 0.90° / tilt 0.76°。
**tilt（可观测）占相当份额**，所以不能全推给规范自由度。

**为什么位置解出的对齐不可信**（`alignment_bootstrap.py`，真实数据、无噪声模型）：
`R_a`（位置导出，门在用）6 段间散度 **12–83°**、随机半长窗对全长 p90 **148°**；
`R_q`（姿态导出）中位 0.51–0.93°。**16–20cm 近直线轨迹上 Umeyama 的旋转近乎退化。**

**ATE 没有局部病灶**（`ate_time_localization.py`，8 cell）：误差²中前 10% 时间占 7%、
前 25% 占 23%（均匀应为 10%/25%），峰值时刻分散在 +6.1/15.0/15.6/16.9/18.6/36.2/36.3/36.4s。
⇒ **「开头关键帧空洞」不泛化**，与既有「补空洞使段间互差减半但整体指标全变差」一致；
压 ATE 只能靠**全局**手段（更长回路 / 更好前端），不能靠修某一段。

**并行否掉的**：内部时间偏移（±100ms 平坦）、加速度计判常量归属（本数据不可用，
**非**原理不可能）、配置外参为主犯（曾据 `C=E⁻² ⇒ |E|≈|C|/2` 推 0.7–0.9°，
**该推导已作废** —— `C = C_gt⁻¹·C_vins` 是**差**不是和，不能反解 |E|；
仍立的结构事实是 GT body 系 = `tracker_T_cam ⊗ inv(body_T_cam0_配置)`，
配置误差必进 GT 且 GT 自查看不见，但量级只 ~0.1–0.5°）。

**开源通行做法**（用户要求调研）：VIO 规范自由度是 **4 维**（位置 + 绕重力轴 yaw），
标准口径 `align_type=posyaw`（rpg_trajectory_evaluation）；**evo 没有这个选项**，
其 `PosePath3D.align()` 正是「位置解对齐再套到姿态上」。Monte Carlo：平滑形变
3mm→1.95°、5mm→2.97°（白噪声 5mm 只 0.55° ⇒ **是形变不是噪声**）。

## 门限分解（18 个可比 cell，现役 G2）

```
完整门 1/18 | 放开 max 5/18 | 放开 rot 2/18 | 同时放开 max+rot 10/18
max 超 10mm 的 16/18, rot 超 2.0° 的 12/18, 而 rmse 中位仅 5.53mm
```

⇒ **典型精度远好于门限，卡人的是尾部(max)与姿态(rot)。**

**★ 09-14 holdout 的平移已经复原**：`v11b3/group2/sparse` = rmse 4.70 / max 8.33 /
w10 100.0 / **零个样本超 10mm**，**唯一失败原因是 `rot 2.08 > 2.0`**；
同 take 的 tight 是 PASS（max 9.79 / rot 1.89）。

## ★ 旋转的预算：一半以上是常量姿态偏移

官方打分用 `rigid_align` 由**位置**定 R。改用**姿态**最优的 Rc
（`min‖A−Rc·B‖_F` ⇒ `Rc=U·diag(1,1,det(UVᵀ))·Vᵀ`, `A·Bᵀ=U·S·Vᵀ`）
再对齐后：

- rot 中位 **1.99° → 1.18°**（降幅中位 0.81°，最大 2.00°）
- **姿态最优后超 2.0° 的 cell: 0/22**
- 常量偏移 `Rc·Rᵀ` 夹角 **中位 1.52° = 2.0° 门限的 76%**
- 同一 take 的 sparse/tight 残差**几乎逐位相同**（1.18/1.18、0.76/0.76、1.42/1.42…）
  ⇒ **每 take 一个常量**，不是随机噪声
- 自洽核对：`√(1.99²−1.18²) = 1.60° ≈ 实测 1.52°`
- ⚠ **轴向在 take 间不一致**（(0.70,0.16,0.70) / (0.04,0.67,0.74) / (0.44,0.44,0.78) …）
  ⇒ **不是**一个全局标定常数，是**每 take 的姿态偏置**（陀螺 bias / 重力初始化一类）

## ★★ 常量偏移归谁：**融合根本不贡献姿态**

直接把 ④fused 姿态与 ①VINS 姿态比（**必须先归到共同 GT 栅格**再比 ——
两条链的 `val` 掩码不同，不归栅格会因长度不等被整片跳过，曾因此只看到 6/20）：

**n=20，剥掉一个常量旋转后残差 中位 0.0000°、最大 0.0084°（浮点噪声），20/20 ≈0。**
常量旋转 ~110.5–111.6°。

⇒ **fused 姿态 ≡ VINS 姿态 × 常量旋转。融合只融位置，姿态是 VINS 原样搬的。**

推论（这是"下一步该修哪"的答案）：

1. **rot 这道门 100% 由 VINS 决定**，融合改不了。
2. VINS 真实姿态噪声仅 **1.22°**，**本就在 2.0° 门内**。
3. 顶过门的是**位置与姿态互不自洽**的 **1.64°** 常量偏移（官方门用**位置**定 R）。
   预算自洽：`√(1.22² + 1.64²) = 2.05° ≈ 实测 r1 1.99°`。
4. ⇒ **修好位置-姿态自洽性，rot 每格都能过门**，且这**不是**"调姿态参数"
   ⇒ [[vins-config-optimal]]（别再调参）与 [[fusion-scale-gate-umeyama-check]]
   （换陀螺姿态更差 78%）的警告**都不挡这条路**。

⚠ 口径：姿态最优对齐是**诊断**，不是官方门的做法。"降幅 0.81°"≠"换对齐就能过门"，
要过门得让**位置与姿态互相自洽**。

## ★★ 那个常量偏移的来源：旋转漂移，且**位置数据本来就分辨不出来**

`attitude_offset_source.py`。

1. **否掉尺度伪影**：Procrustes 里尺度与旋转**解析解耦**（尺度由 ‖A‖ 定、旋转由 `A·Bᵀ` 的
   SVD 定）⇒ 换 similarity 的 R 得到**逐位相同**的偏移。结构上必然，算否证不算发现。
2. **是旋转漂移的签名**：轨迹切两半各自 `rigid_align`，两 R 夹角 = 半段漂移；
   `rigid_align` 落在漂移中点、姿态不跟着漂 ⇒ 差一半。
   `VINS 偏移 3.00° / 半段漂移 3.83° = 1.49`。
3. **融合修掉大半，且全是位置侧**：偏移 3.00°→1.57°、半段漂移 3.83°→1.10°。
   姿态是**逐位相同**的（见上）⇒ off 的任何变化**只可能来自位置侧**。
4. **★ 残留 1.57° 落在【位置分辨带】里**：半径中位 15.9cm、位置 RMSE ~2.6mm
   ⇒ 位置能分辨的最小旋转 `atan(位置RMSE/半径) ≈ 1.75°`；
   换姿态最优 R 位置 RMSE **只涨 +1.40mm**（埋在位置噪声里）。
   **⇒ 这 1.57° 的旋转，位置数据本来就定不出来。**

### ⇒ rot 门的地板 ≈ 2.11° > 门限 2.0° —— **门在地板下面**

```
rot = √(1.18² + 1.75²) = 2.11°   门限 2.0°
```

**16cm 半径的桌面轨迹上这道门就是掷硬币，不是调参问题。**
与 [[vins-config-optimal]]「别再调参，要更高精度**换更大回路**」**互相印证**
（半径越大，同样位置精度给的角分辨率越高）。
⚠ 口径：「分辨带」= 位置RMSE/半径 的一阶估计，够说明量级，不是严格可观测性分析。
