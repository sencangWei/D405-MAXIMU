## ① 失败分两个物种（18 个可比 cell，现役 G2）

```
超标(>10mm)样本数 <=5 个:  5/18      超标 >=20 个: 13/18      中间几乎没有
```

| 类 | 例 | 超标数 | 占比 | 最长段 | 去掉最坏5个后 |
|---|---|---|---|---|---|
| **A 孤立离群** | `v10/g1/sparse` | **2** | 0.11% | 0.03s | **<10mm** |
| | `v11b3/g1/sparse` | **5** | 0.29% | 0.13s | **9.95** |
| | `v11b3/g2/sparse` | **0** | 0% | — | （max 8.33，**只卡 rot**）|
| **B 结构性** | `v10/g2/tight` | **368** | 21.1% | **9.63s** | 17.26（几乎不动）|
| | `batch5/g3/tight` | **378** | 21.7% | 7.80s | 17.98 |

```
去掉最坏 1 个就 <10mm: 2/18      去掉最坏 5 个就 <10mm: 5/18
超标<=5 的 5 个 cell, 去 5 个后【全部】<10mm (9.42–9.95)
```

⇒ **A 类里有 3 个只差 1–2 个采样点**（30Hz 下就是 1–2 帧）。
⇒ **A 与 B 是两种病**：A 要鲁棒性/离群抑制，B 要上游结构精度。
**别用同一个结论去解释两类。**

## ② ★ 误差在【录制的固定时刻】，可复现

sparse 与 tight 是同一录制**不同的帧子集**、**两次独立**跑。取两边超 10mm 时刻的交集：

```
v10/g1         sparse   2 / tight   2   重合   2
batch5/g2      sparse  30 / tight 169   重合  30
batch5/g4      sparse  41 / tight  20   重合  20
collective/g1  sparse 154 / tight 178   重合 106
```

⇒ 两次独立跑误差落在**同一时刻** ⇒ **录制的属性（那一刻的场景/动作），不是算法随机抖动**。
这是 [[spike-attribution-20260919]]「动作激烈 19/19」的**直接证据**（随机抖动不会重合）。
⇒ 推论：**这些失败可定位、可复现**，能指到具体哪一刻。

**③ A 类的坏点归谁：在估计侧，不是真值伪影。** 测真值自身单点尖峰
`|GT[i]−(GT[i−1]+GT[i+1])/2|`：超标处真值尖峰 2.51/0.81/0.61mm，
而误差 12.31–13.06mm ⇒ **真值干净**，问题在估计侧。

**④ ★ 但"尖峰/跳变"这个机理描述是错的。** 两条药方**都被实验否掉**
（`despike_experiment.py`，用扫描器自己的 `score()`）：

- **时间维滤波无效**：raw 13.73 → gauss.025 / hampel_w3,w5,w9 / median_w3,w5 **全部 13.74**
  （差 <0.03mm）；加重平滑反而更糟（gauss 0.1→13.85，0.2→34.02）
- **时间位移也无效**：扫 ±60ms，最优位移在 take 间乱跳（0/10/20/30/−20ms），
  max 改善中位仅 **0.81mm** ⇒ **不是常量时间偏移**

**⑤ ★★ 2026-09-20：「快速段欠走」这个后续机理【也作废】。**
当时读 `v10/g1/tight` 峰值 ±8 帧表（误差 `6.7…13.7…1.2`、真值步进 7.9 / 估计 4.8）
读成"估计少走位移"，错在四处：

1. **算不出来**：该帧步进差只有 **0.1mm**，而误差 **7.4mm**（次帧 13.7）——差两个数量级。
2. **整链不存在**：`cumsum(真值步进−估计步进)` 在峰值处 **−7.91mm（负的，估计走多了）**，
   `corr(累计欠走, 误差) = −0.456`，路径比 0.9809 ⇒ **反相关**。局部窗口：误差爬升 10.75mm
   而欠走只爬 2.95mm ⇒ 至多解释 **27%**，峰后误差回落而欠走继续涨 ⇒ **反号**。
3. **方向不对**：峰值帧 `13.16 = 沿航向 6.55 + 垂直 11.42`，**垂直占 87%**（整链中位 79%）。
   "欠走"是沿航向的故事，误差长在**垂直**方向。
4. **观测假象**：整链估计**步进 p95 = 7.08mm，真值 7.26mm** —— 估计走得动，
   "恒 4.0–4.8"只是挑的那 16 帧窗口如此。

⇒ **五条假设逐条排除**（`peak_chain_attribution.py`，靶=`v10/g1/tight` 帧 469）：
欠走 / 过度平滑 / tracker 换分支（**0 次切换**，门 PASS）/ 姿态×力臂（力臂实测仅 **~30mm**，
出 11mm 需 21.7°）/ 绕远点缓慢旋转（残差⊥半径中位 0.669、corr(\|残差\|,半径) +0.1~0.2、
峰值残差与前 100 帧**反号**）。

**仍然立得住的**（`E.interpolate_ground_truth` + 窗口内 `rigid_align`，同口径）：

```
④fused未平滑 [8/9] 11.23mm   ⑤fused 11.25mm   VINS 11.02mm
③graph [7/8]        1.51mm  ⚠【相机系】与体真值非同系，不可直读
```

- **融合位置几乎就是 VINS 位置**（11.23/11.02 = 1.020）；**换代无关**（旧代 G1 11.20）。
- 但 `fusion_report.json` 的 **`injected_correction_max_mm = 4.44`**（全链最大注入）
  ⇒ [8/9] 距 conv(③) ≤4.44mm ⇒ **峰值 11.2mm 里至少 6.8mm 在 [8/9] 之前**。
- **窗口净位移**（全局对齐后）：±15 帧 ⑤ 航向差 **0.64°**/横向 1.39mm，VINS 3.25°/6.94mm；
  ⇒ **融合峰窗内自己走得对**，11mm 是**窗口首尾同样存在的局部偏移**，**不是累积漂移**。

⇒ 至此只确定：**垂直航向的 ~0.3s 局部偏移块**，发生在真值直线加速处，估计比真值平滑，
**成因仍未定位**。**"尾段补不了"仍成立**（注入上限 4.44mm 够不着 11mm）。

**⚠ 三个口径坑**：① `interpolate_ground_truth` 的 `itp`/`iq` **已按 `ins` 收窄**
（长度 = `ins.sum()` ≠ `len(t_est)`）；② **估计与真值不同世界系**（MASt3R vs tracker 体 **差约 90°**），
任何净位移/航向比较**必须先 `rigid_align`**，否则得到恒等于 `90.00°` 的假航向差；
③ `np.interp` 的 `xp` 不覆盖 `x` 时**常量外推**，链间时钟基不同时不可直接用。

## ③ 度量尺度来源：**双目并不更准**（关掉一个悬着的决策）

`imu_scale_report.json:scale` 与四份 `stereo_scale_*:scale_m_per_mast3r_unit`
是**同一物理量**（米/MASt3R 单位），可与真值（`trajectory_frames` 对 GT 的相似尺度）直接比：

```
IMU 偏差 中位 5.94%      双目偏差 中位 5.26%      双目更准 10/23 (掷硬币)
两者【同向偏大】~5%      IMU-双目分歧 中位 2.76%   超 15% 硬门 0/23
```

⇒ **两个独立度量参考都说 MASt3R 那套单位偏小 ~5%**（都同向，值得单独追）。
⇒ [[codex-gate-blindspot-history]] 的「尺度交给双红外」策略**在本批数据上没有收益依据**。
⚠ 不等于那个 15% 硬门不存在，只是**这 23 个 cell 上一次都没触发**。

## ④ 最终产物的尺度**不是** max 的驱动

```
融合产物尺度偏差 中位 +0.52% (-2.05 ~ +2.30%)
corr(|尺度偏差|, max) = -0.042      corr(·, rmse) = +0.126
```

⇒ 融合已经把尺度修好，`max` 不赖尺度。**别再往尺度方向查 max。**
