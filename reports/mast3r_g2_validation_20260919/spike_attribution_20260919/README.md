## 〇、★ 更正：生产链是一条链，不是四条平行链

我在分析中途把产物目录里的四个 `trajectory_*.csv` 当成了四条平行链：

| 我当时的叫法 | 文件 | 当时以为的 | **实际** |
|---|---|---|---|
| ⓐ 原始 | `trajectory_frames.csv` | 链头 | ✅ 链头 |
| ② 图 | `trajectory_graph.csv` | 与 ③ 并列的兄弟 | **④ 融合的输入** |
| ③ 图+度量 | `trajectory_imu_metric.csv` | 与 ② 并列的兄弟 | **② 的输入** |
| ④ 融合 | `trajectory_fused.csv` | 链尾 | ✅ 链尾 |

读 `scripts/mast3r_slam_precision_workflow.sh` 即可确认（一条链）：

```
[6/8] align_mast3r_scale_with_imu.py        --trajectory trajectory_frames.csv
                                            --output     trajectory_imu_metric.csv
[7/8] fuse_mast3r_stereo_imu.py             --trajectory trajectory_imu_metric.csv
                                            --output     trajectory_graph.csv
[8/9] fuse_docker2_mast3r_complementary.py  --mast3r     trajectory_graph.csv
                                            --output     trajectory_fused_unsmoothed.csv
[9/9] smooth_pose_trajectory.py             --input fused_unsmoothed --output trajectory_fused.csv
```

⇒ 据此得出的「**②→③ 让误差从 32.27 恶化到 41.81**」是**把管线读反了**：
`imu_metric` 在 `graph` **上游**，是图优化**改善**了形状，不是某一步恶化了它。

⇒ 另一处更隐蔽的错：`rigid_align` **不估尺度**，所以它的残差**强烈依赖输入的绝对尺度**。
原始帧轨迹比真值大 2.8 倍，那个被我一直当作「形状误差 810mm」的数，
**绝大部分是「太大」贡献的，不是形状**。要量形状，必须先按相似变换把尺度归到 1.0 再 `rigid_align`。

跑 `chain_topology.py` 可复现全部三点。

## 三、画面/光照：强光过曝假设被【实测否掉】

- **Y 通道实测 min 16 / max 235，≥240 占比 0.0000%** ⇒ 整条录制**零过曝**。
- 亮度与误差 **负相关 ρ=−0.173**（越亮误差越小）：
  最亮 5% 帧误差中位 **3.18mm** < 全部帧 4.15mm < **最暗 5% 帧 4.66mm**。
- 效应量排名（|Spearman ρ|）：**GT角速度 +0.282 > 线速度 +0.230 > 清晰度 −0.228 > 亮度 −0.173 > 低纹理% +0.174**。
- 红外通道同样否掉：IR ≥250 占比最高 0.154%，且**饱和帧误差反而更低**（3.50 vs 4.20mm）。
- 场景（实看帧）：高反光深色亮面木桌（镜面反射红碗/显示器/线缆）+ 画面中下部大面积**深色低纹理双叉件**；
  某些帧有**正在发光的显示器**，另加**基站的 IR 发射**。
  ⇒ 反光/低纹理是真实场景风险，但**不是靠过曝起作用**。

> ⚠ 曾经用「误差最大 6 帧 vs 最小 6 帧」对比得出「亮斑 0 个 vs 12 个」，**那是选取假象**：
> 放到全部 1743 帧上，亮斑数对误差**没有预测力**（ρ=0.033）。
> 屏幕上的「显示器+夹爪 vs 空桌面」强对比同样是选取假象 / 与轨迹位置混淆。

### 旋转的预算：一半以上是【常量姿态偏移】

官方打分用 `rigid_align` 由**位置**定 R。若改用**姿态**最优的 Rc 再对齐：

```
位置对齐后 rot 中位 1.99° → 姿态最优后 1.18° (降幅中位 0.81°)
姿态最优后超 2.0° 的 cell: 0/22
```

常量偏移 `Rc·Rᵀ` 夹角 **中位 1.52°，占 2.0° 门限的 76%**。
且同一 take 的 sparse/tight 残差几乎逐位相同（1.18/1.18、0.76/0.76、1.42/1.42…）
⇒ 这是**每 take 一个常量**，不是随机噪声。

⚠ **但轴向在 take 之间不一致**（(0.70,0.16,0.70) / (0.04,0.67,0.74) / (0.44,0.44,0.78) …）
⇒ **不是**一个全局标定常数，是**每 take 的姿态偏置**（陀螺 bias / 重力初始化一类）。
自洽性核对：√(1.99² − 1.18²) = 1.60° ≈ 实测 1.52°。

### 逐链 rot（注意 ②③ 的 91° 是坐标系约定，不是误差）

```
①VINS       n=21  中位  3.27°  超2.0的 21/21  最大 13.18°
③imu_metric n=23  中位 91.07°  超2.0的 23/23  最大 92.22°   ← 重力 bake 约定
②graph      n=22  中位 91.41°  超2.0的 22/22  最大 92.70°   ← 同上
④fused      n=22  中位  1.99°  超2.0的 10/22  最大  3.18°
```

⇒ **旋转误差由 VINS/IMU 姿态链主导**（中位 3.27°），融合把它压到 1.99°——正好压在门线上。
⇒ 与 [[fusion-scale-gate-umeyama-check]] 的"视觉姿态自身误差 1.3–2.4°"、
[[vins-config-optimal]] 的"别再调参"相互印证，**动姿态参数前先回看这两条**。

## 四之三、★ 那个常量偏移归谁：**融合根本不贡献姿态**

直接把 ④fused 的姿态与 ①VINS 的姿态比（先归到**共同 GT 栅格**再比；
两条链的 `val` 掩码不同，不归栅格会因长度不等被整片跳过）：

```
n=20  剥掉一个常量旋转后残差 中位 0.0000°  最大 0.0084°(浮点噪声)
残差 ≈0 的 cell: 20/20
```

**⇒ fused 姿态 ≡ VINS 姿态 × 一个常量旋转（~110.5–111.6°）。**

融合**不贡献任何姿态信息**——它只融位置，姿态是 VINS 原样搬过来的。
所以：

1. **rot 这道门 100% 由 VINS 决定**，融合改不了。
2. VINS 的真实姿态噪声只有 **1.22°（r2 中位）**，**本就在 2.0° 门内**。
3. 把格子顶过门的是**轨迹位置与姿态互不自洽**那 **1.64°** 常量偏移
   （官方门用**位置**定 R，两者不一致就吃罚）。
   预算自洽：`√(1.22² + 1.64²) = 2.05° ≈ 实测 r1 1.99°`。

⇒ **只要把位置-姿态的自洽性修好，rot 这一项每个 cell 都能过门**，
   而且这**不是**"调姿态参数"——记忆里 `vins-config-optimal`（别再调参）与
   `fusion-scale-gate-umeyama-check`（换陀螺姿态更差 78%）的警告都不挡这条路。

### ⚠ 口径：姿态最优对齐是**诊断**，不是官方门的做法

官方门用 `rigid_align` 由**位置**定 R。"降幅 0.81°"**不等于**"换个对齐就能过门"——
要过门得让轨迹的**位置与姿态互相自洽**。这个区别决定下一步是查根因还是白费功夫。

## 四之四、★ 那个常量偏移从哪来：**它是旋转漂移，而且位置数据本来就分辨不出来**

`attitude_offset_source.py`。追 四之三 / 四之二 里那个 1.52° 常量偏移的来源。

### ① 否掉「尺度伪影」

Procrustes 里**尺度与旋转解析解耦**（尺度由 ‖A‖ 定，旋转由 `A·Bᵀ` 的 SVD 定），
换 similarity 的 R 得到**逐位相同**的偏移（3.00°→3.00°、1.65°→1.65°…）。
⇒ 偏移与尺度无关。这条能否掉，但**在结构上必然如此**，算否证不算发现。

### ② 是「旋转漂移」的签名

轨迹切两半、各自 `rigid_align`，两个 R 的夹角 = 半段漂移。
`rigid_align` 会落在漂移的**中点**，姿态不跟着漂，于是差一半：

```
VINS   偏移中位 3.00°   半段漂移中位 3.83°   off/(漂移/2) = 1.49
```

### ③ 融合修掉大半，而且**全是位置侧的功劳**

```
             偏移      半段漂移
VINS        3.00°      3.83°
fused       1.57°      1.10°
```

姿态是**逐位相同**的（四之三：fused ≡ VINS × 常量），
⇒ **off 的任何变化只可能来自位置侧** ⇒ 融合的位置修正确实在收这个口子。

### ④ ★ 残留的 1.57° 落在【位置分辨带】里

```
轨迹半径中位 15.9cm, 位置 RMSE 中位 ~2.6mm
⇒ 位置数据能分辨的最小旋转 = atan(位置RMSE / 半径) ≈ 1.75°
⇒ 把位置最优 R 换成姿态最优 R, 位置 RMSE 只涨 +1.40mm (埋在位置噪声里)
```

**⇒ 这 1.57° 的旋转，位置数据本来就定不出来。**

### ⑤ 结论：**rot 门的地板 ≈ 2.1°，门限 2.0° —— 门在地板下面**

```
rot = √(VINS姿态噪声² + 常量偏移²) = √(1.18² + 1.75²) = 2.11°   门限 2.0°
```

在 **16cm 半径的桌面轨迹**上，这道门本身就是**掷硬币**，**不是调参问题**。
这与 [[vins-config-optimal]] 从完全不同的方向得出的
「别再调参，要更高精度**换更大回路**」**互相印证**——
半径越大，同样的位置精度给出的角分辨率越高。

> ⚠ 口径：④⑤ 里的"分辨带"用的是**位置 RMSE / 半径**这个一阶估计，
> 不是严格的可观测性分析。它足以说明量级，不足以当定理用。

**A 类里有 3 个只差 1–2 个采样点。** 它们和 B 类是**两种病，要两种药**。

### ⑤ ★ 误差出现在**录制的固定时刻**，可复现

sparse 与 tight 是同一录制**不同的帧子集**、两次**独立**跑。
把两边的超 10mm 时刻取交集：

```
v10/g1        sparse    2 / tight    2   重合    2
batch5/g2     sparse   30 / tight  169   重合   30
batch5/g4     sparse   41 / tight   20   重合   20
collective/g1 sparse  154 / tight  178   重合  106
```

⇒ **两次独立跑，误差落在同一时刻** ⇒ 是**录制的属性**（那一刻的场景/动作），
**不是算法随机抖动**。这和 二、的「动作激烈 19/19 cell 角速度 2.47x」是同一件事，
但这里是**直接证据**：如果是随机抖动，两个子集不该重合。

⇒ 推论：**这些失败是可定位、可复现的** —— 能指到具体是哪一刻。

### ⑦ ★ A 类不是尖峰 —— 但"快速段欠走"这个机理**已于 2026-09-20 被否**

**先试了「时间维鲁棒性」这条药方 —— 被实验否掉**（`despike_experiment.py`）：

**滤波逐位无效**（差 <0.03mm），而且加重平滑会**更糟**。← 这一条**仍然成立**。

**当时拿下面这张 ±8 帧表去解释它**：

```
误差(mm):   6.7 8.4 6.7 5.3 7.5 7.6 10.0 12.8 13.7 9.9 6.2 3.4 2.9 1.3 0.8 1.1 1.2
估计步进:   3.9 4.0 4.0 4.0 4.0 4.1 4.5 4.8 4.8 4.8 4.8 4.8 4.7 4.7 4.7 4.5
真值步进:   4.1 4.7 4.6 3.7 4.4 3.8 4.3 4.4 7.9 7.0 6.3 5.0 5.6 5.7 4.0 4.7
```

当时读成"估计在快速段**欠走**（少走位移），随后追上"。**这个读法是错的**，
错在两处：

**① 算不出来。** 峰值那一帧步进差只有 `4.8 − 4.9 ≈ 0.1mm`，而该帧误差是
**7.4mm**（下一帧 13.7mm）。单帧步进差**不可能**解释两个数量级之外的误差。

**② 整链上"欠走"根本不存在。** 全链累计欠走积分 `cumsum(真值步进 − 估计步进)`
在峰值处是 **−7.91mm（负的，估计走多了）**，`corr(累计欠走, 误差) = −0.456`，
整条路径比 **0.9809**（估计 3235.5mm vs 真值 3298.4mm）⇒ **反相关**。
局部窗口（锚 457 帧）同样：误差爬升 **10.75mm**，累计欠走只爬升 **2.95mm**
⇒ 欠走至多解释 **27%**，峰值之后误差回落而欠走继续涨到 11.41mm ⇒ **反号**。

**③ 方向也不对。** 峰值帧 `13.16mm = 沿航向 6.55 + 垂直 11.42`，**垂直占 87%**；
整链中位 79%、误差 >8mm 的样本 90% 是垂直分量。**"欠走"是沿航向的故事，
而误差长在垂直方向。**

**④ 那张表还有一个观测假象。** "估计步进恒 4.0–4.8"只是**挑的那 16 帧窗口恰好如此**。
整链上估计的**步进 p95 = 7.08mm，真值 7.26mm** —— 估计走得动，不是被平滑死了。

**那是不是时间偏移？也不是**（扫 ±60ms，用同一个 `score()`）：

```
最优位移在 take 之间乱跳: 0 / 10 / 20 / 30 / −20 ms
位移带来的 max 改善: 中位 0.81mm, 最大 1.90mm
（δ=0 已经是最优的那个 cell 正是唯一 PASS 的 v11b3/g2/tight）
```

⇒ 不是常量时间偏移，时间对齐修不了它。

|---|---|

1. `E.interpolate_ground_truth` 返回的 `itp`/`iq` **已经按 `ins` 收窄**，长度 = `ins.sum()`

3. `np.interp` 的 `xp` 不覆盖 `x` 时**常量外推**；链的时钟基不同，别拿它直接插。

⇒ 结论：**"快速段欠走"作废。** 目前只确定：这是**垂直航向的、~0.3s 的局部偏移块**，

⇒ 要提前这个关键帧**只能动 rotation**。第一版设计作废，改做下面这个。

### ② 收紧 `motion_keyframe_rotation_deg` 5.0 → 1.0：**只挪了 4 帧**

| | 第一个关键帧 | 触发时 rotation | 触发时 translation | 帧 ≤226 的关键帧数 |
|---|---|---|---|---|
| 基线 `5.0°` | 帧 **226**（t=7.53s） | 5.753° | 0.0245 | 1 |
| 变体 `1.0°` | 帧 **222**（t=7.37s） | 1.013° | 0.0075 | 4 |

阈值确实生效了（之后变体几乎逐帧触发：222,224,225,226,…），**但第一个关键帧只提前 0.13s**。

原因看触发值就清楚：**前 7.37s 的「视觉 vs IMU 先验旋转分歧」一直 <1°**，帧 222 才到 1.013°，
帧 224 到 2.073°，之后持续在 1–2.5°。**这个信号在静止段是平的**——
⇒ **阈值这个杠杆根本够不到那个空洞**，任何低于 5.0 的阈值都只能把第一个关键帧放在 **222–226** 之间。

### ③ 而且这个旋钮是**全局**的，做不出干净对照

收到 `1.0°` 不是"只把开头变密"，是**整条轨迹都换对象**：


### ⑤ 两个必须立住的对照（否则上面全部不成立）

**(a) 前端是确定性的、且我的 scratch 调用与生产等价。** 用**同一命令行**把配置换回 `5.0°` 重跑：

```

trajectory_frames.csv: 与生产【逐位相同】(最大逐元素差 = 0.000e+00)
```

⇒ ② 里变体序列的差异**可以干净地归给配置**，不是调用方式或环境差异。

**(b) `aged_translation` 的合适量级是【实测】出来的，不是猜的。**
触发器比的是「当前帧相对上个关键帧的平移」，这个量就在 `trajectory_frames.csv` 里：

```
帧    5 (t=0.17s): 2.0e-05        帧  144 (t=4.79s): 2.6e-05
帧   15 (t=0.50s): 2.1e-05        帧  180 (t=5.99s): 2.2e-05
帧   60 (t=2.00s): 4.8e-05        帧  226 (t=7.53s): 2.54e-02   ← 跳变

```

⇒ 开头 6 秒累计平移只有 **2e-5 MASt3R 单位 ≈ 0.009mm**。
**既有配置用的 `aged_translation` 是 0.01 / 0.08 —— 在这个 take 上永远够不着。**
旁证：`dense_motion_kf_v1`（`rot 2.0` + `max_gap 30` + `aged 0.01`）在它那条 take 上
**第一个关键帧迟至帧 771**，正是同一个原因。

⇒ 同时它也说明：**真正"该有第二个关键帧却没有"的窗口是 [帧 144, 226]（t=4.8→7.53s）**
——那段**有转动、几乎没平移**，不是静止的开头。

### ⑥ 对的那个杠杆：`aged_motion`（补空洞，不改阈值）

`motion_keyframe_trigger()` 里的 `aged_motion` 要求 **`frame_gap >= maximum_frame_gap`**，
也就是**只在"距上个关键帧已经很久"时才可能触发** —— 它**恰好只补空洞**，
而空洞正是没有运动触发的地方。**阈值（0.15 / 5.0）一个字不用改。**

配置：`config/mast3r_slam_d405_offline_motion_kf_agedfill.yaml`
（`max_gap_frames: 15` + `aged_translation: 1e-6`，其余与 `..._motion_kf_tight.yaml` 逐字相同）。

**实测它确实把关键帧放进了开头**（`translation=0.0000, rotation=0.000deg` ⇒ 是 aged 触发的）：

```
Motion keyframe 15 / 30 / 45 / 60 / 75 / ...   ← 每 15 帧一个
```

> ⚠ **已知风险，不隐去**：这样补出来的关键帧**基线近似为 0**（开头几乎只有旋转），
> 而运动门控本来就是为了避免零基线关键帧。所以**若结果变差，不能直接读成"洞不是原因"**，
> 也可能是"零基线关键帧本身有害"。**这两种解释本轮分不开。**

### ⑦ ★ 结果：**两件事同时发生** —— 机理被证实，但它不是修法

跑完 204 个关键帧（基线 151，`done` / `rc=0`）。

**这个杠杆非常干净**：`帧 ≤411` 时 agedfill 51 个关键帧 vs 基线 37 个，**多出的正好 14 个**；
而它在开头（`帧 ≤226`）补了 **15** 个、基线只有 **1** 个。
⇒ **aged 只在开头生效，轨迹其余部分的关键帧一个都没动**（别处运动触发本来就密，间距到不了 15 帧）。

```
运行              切点s   头残差   尾残差   段间互差   夹角    rmse①   p95①   max①   w10①
基线 rot=5.0       7.53    3.75    12.34    17.68    8.71    20.62   36.50   52.51   16.6
对照 5.0（重跑）    7.53    3.75    12.34    17.68    8.71    20.62   36.50   52.51   16.6  ← 与基线逐位相同
agedfill           7.53    2.63    14.61     8.88    6.73    23.85   44.31   61.13   19.9
```

> ⚠ **`rmse①/p95①/max①/w10①` 是【① 前端原始轨迹 × scale】的数，不是产品链的，不可对门限读。**
> 产品链还要过 [7/8] 图优化与 [8/9] 融合（本目录 ③ 就是实例：① 3.75/12.34 → ④ 0.82/4.70）。
> 这四个数在这里**只用于 A/B 横向比较**。

**读法（两件事必须一起读，不能只挑一件）：**

1. **✅ 开头的空洞【确实】是那 15mm 的贡献者。** 把关键帧补进空洞后，
   **段间互差从 17.68mm 减半到 8.88mm**、**夹角从 8.71° 降到 6.73°**、头段残差 3.75 → 2.63。
   ⇒ ③ 里"成因仍是空白"这句现在可以收窄：**不是全部成因，但它是一个真实且可复现的贡献者。**
2. **❌ 但它不是修法。** 四项整体指标**全部变差**（`max①` 52.5 → 61.1，`p95①` 36.5 → 44.3），
   尾段对真值的拟合也从 12.34 恶化到 14.61。⇒ **补出来的关键帧让整条解更"自洽"了，但更不准了。**
3. **⚠ 两种解释本轮分不开**（见 ⑥ 的风险注）：变差既可能是"零基线关键帧本身有害"，
   也可能只是"这一组补法不好"。**本轮没有做更松的补法（如 `max_gap 30`）来分开它们。**

⇒ **这条线索的净结论**：**空洞是真的、且确实在造这 15mm 的一部分；但用配置补它换来的是整体误差上升，
所以它不是一条能走通的修法。** 结合 ④（段间位移**不是**门判别量，PASS 那条正好在中位），
**不建议沿着"补开头关键帧"继续投入。**
